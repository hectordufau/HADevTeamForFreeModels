# HADevTeamForFreeModels V3.0 — Validation Protocol

> **Status:** Ready for Execution
> **Baseline:** v3.0.0 (frozen)
> **Objective:** Prove that the Learning Engine produces measurable engineering improvement.
> **Decision Gate:** V3.1 (improve learning) vs V4.0 (autonomous engineering)

---

## 1. Protocol Overview

```
V3.0.0
  │
  ├─ VALIDATE-001 — Freeze release (config, code, models)
  ├─ VALIDATE-002 — Benchmark protocol lock
  ├─ VALIDATE-003 — Baseline runner (10 scenarios × 5 runs = 50 executions)
  ├─ VALIDATE-004 — Collect baseline metrics
  ├─ VALIDATE-005 — Enable Learning Loop
  ├─ VALIDATE-006 — Re-execute benchmark (10 × 5 = 50 runs with learning)
  ├─ VALIDATE-007 — Measure Learning Gain
  ├─ VALIDATE-008 — Generalization test
  ├─ VALIDATE-009 — Failure→Learning→Recovery test
  ├─ VALIDATE-010 — Generate Validation Report
  │
  └─ DECISION GATE ─► V3.1 or V4.0
```

## 8. Learning Gain Calculation

Compare baseline vs learning:

```python
def learning_gain(baseline: dict, learning: dict) -> dict:
    return {
        "success_rate_delta": learning["success_rate"] - baseline["success_rate"],
        "mean_score_delta": learning["mean_score"] - baseline["mean_score"],
        "mean_correctness_delta": learning["mean_correctness"] - baseline["mean_correctness"],
        "mean_security_delta": learning["mean_security"] - baseline["mean_security"],
        "mean_architecture_delta": learning["mean_architecture"] - baseline["mean_architecture"],
        "mean_iterations_delta": baseline["mean_iterations"] - learning["mean_iterations"],
        "mean_latency_delta": baseline["mean_latency"] - learning["mean_latency"],
        "replan_rate_delta": baseline["replan_rate"] - learning["replan_rate"],
    }
```

Positive delta = improvement.

## 9. Generalization Test

This is the most important test.

**Protocol:**

1. Execute BENCH-001 (CRUD API) 5 times → collect learning
2. Execute BENCH-002 (Authentication) 5 times → BENCH-002 is a DIFFERENT task
3. Measure: does BENCH-002 performance improve because of BENCH-001 experience?

```python
generalization_gain = (
    performance(BENCH-002, after_learning_BENCH_001)
    - performance(BENCH-002, baseline)
)
```

If `generalization_gain > 0`, the system **generalizes**.

---

## 10. Failure → Learning → Recovery Test

**Protocol:**

1. Create a task designed to fail (e.g., wrong framework, missing dependency, ambiguous requirement)
2. Execute: failure → FailureAnalyzer → root cause → lesson → Memory → Replanner → recovery → success
3. Verify: lesson is stored in Memory
4. Create a similar task
5. Execute: Harness uses lesson → avoids failure → passes

**Acceptance:**

```
Lesson generated:              YES
Lesson stored to memory:       YES
Re-execution uses lesson:      YES
Failure avoided:               YES
```

## 13. Decision Gate

After the report is generated, the agent must evaluate:

| Condition | Result |
|---|---|
| Learning Gain (score) > 0.05 | PASS else FAIL |
| Learning Gain (success rate) > 5% | PASS else FAIL |
| Generalization Gain > 0 | PASS else FAIL |
| Failure → Learning → Recovery works | PASS else FAIL |
| Security violations = 0 | PASS else FAIL |
| Governance violations = 0 | PASS else FAIL |

### If ALL conditions PASS:

```
Recommendation: V4.0
Tag: v4.0.0-autonomous-engineering
```

### If ANY condition FAILS:

```
Recommendation: V3.1
Tag: v3.1.0-learning-improvements
Action: Improve Learning Engine (memory retrieval, confidence, statistical methods, exploration)
```

## 15. Agent Execution Rules

1. Do NOT modify any `v3.0.0` code during validation.
2. Do NOT modify benchmark scenarios during validation.
3. Do NOT modify model catalog or policies during validation.
4. Run ALL 312 tests before and after validation to confirm regression.
5. Each execution must have a unique seed for reproducibility.
6. Aggregate results statistically (mean, std dev where applicable).
7. Report ALL results truthfully — negative results are valid data.
8. If validation fails due to infrastructure (no project to test on), report BLOCKED.
