## Key Implementation Details

### 1. Artifact Namespace
Every store computes its namespace path relative to a `base_path` (defaults to `artifacts/v3.2/` from `get_v32_base()`). The path is `<base_path>/<validation_run_id>/<mode>/<store_type>/`.

### 2. Isolation Verifier
`verify_isolation(base_path, run_id)` scans the artifact tree and detects:
- **cold_learned**: Same filename in COLD and LEARNED
- **learned_cold**: Same filename in LEARNED and COLD  
- **test_training**: Same filename in TEST and COLD/LEARNED
- **cross_run**: Same filename in different validation runs
- **unattributed**: Directories not in valid modes

### 3. Retrieval Filtering
`retrieve_filtered(items, context)` filters Python objects by mode and validation_run_id. Used in-store for all retrieval methods. When context is None (backward compat), returns all items.

### 4. TEST Protection
`check_test_protection(context, operation)` raises `ValueError` if TEST-mode artifacts attempt `learn` or `train` operations. The `store` operation is always allowed.

### 5. Backward Compatibility
All stores preserve V3.1 behavior:
- When no `ExperimentContext` provided, fall back to flat V3.1 storage directories
- All existing store method signatures unchanged (context is optional)
- All existing tests pass (520 total)

### 6. Historical V3.1 Artifacts
NOT migrated. Left untouched. The namespace is for NEW V3.2 artifacts only.
