# V3.3 Phase 16 Pre-Experiment Specification

**Scope:** P16.0-P16.6 only. This document is frozen before any accepted run.

## Authorization and stop boundary

This phase prepares and pilots field-validation infrastructure. It does not execute
P16.7 freeze, P16.8 accepted field validation, P16.9 reproducibility verification,
or P16.10 final analysis. No effectiveness claim may be derived from the pilot.

## P16.0 integrity baseline

- Base commit: `edea273b47eba768518500dffe79239f06602457` (`v3.3.0^{}`)
- Baseline suite: 1960/1960 PASS; 1960 tests collected.
- The `v3.3.0` tag and historical V3.0-V3.3 release evidence remain unchanged.

## P16.1 frozen configuration

- Run modes: `CONTROL`, `KNOWLEDGE_ONLY`, `KNOWLEDGE_PLUS_LEARNING`.
- Pilot seed: `20260918`; pilot repetitions: 1 per task/mode.
- Accepted-run repetitions are not activated by this implementation.
- Digests use canonical JSON and SHA-256; Python `hash()` and global RNG are forbidden.
- Statistics are descriptive difference-in-means with a predeclared practical
  threshold of 0.05, alpha 0.05, and deterministic bootstrap/permutation settings
  reserved for the accepted analysis.

## P16.2 benchmark and knowledge dataset

`config/phase16/benchmark.json` contains 20 immutable tasks: two per category
(functional, architecture, security, requirements, NFR, TDR, risk, RCA,
maintenance, irrelevant), with balanced HIGH/MEDIUM/LOW/NONE knowledge-sensitive
labels (five each). Prompts contain no answer, solution, expected-answer, or
scoring leakage. `config/phase16/knowledge.json` contains the corresponding
context-only records and carries no answer field.

## P16.3 metrics and instrumentation

Each observation records run/task/mode/repetition/split, deterministic derived
seed, score, success, retrieval count, influence count, and learning flag.
Configuration, benchmark, knowledge, and observation digests are persisted. The
existing V3.3/Phase 13 infrastructure remains the source of knowledge and
learning semantics; this module introduces no competing `ExperimentContext` or
statistics engine.

## P16.4 isolated runner

The runner deep-copies benchmark and knowledge inputs. Each mode has a distinct
state namespace. CONTROL cannot retrieve knowledge; KNOWLEDGE_ONLY cannot apply
learning; KNOWLEDGE_PLUS_LEARNING is the only mode with learning enabled. TEST is
held out and never trains in the runner contract. Any attempt to construct an
accepted run fails closed.

## P16.5 predeclared analysis and golden tests

`analyze_effect` classifies effects as POSITIVE, NEUTRAL, or NEGATIVE using only
the frozen 0.05 practical threshold. Synthetic golden cases cover all three
classifications. No real pilot result is used to tune the method.

## P16.6 pilot-only execution

The pilot validates loading, immutability, deterministic seeds, artifact schema,
and isolation. It is written to `artifacts/v3.3/phase16/pilot.json` with
`status=PILOT_ONLY` and `accepted_run_executed=false`. Pilot observations are
infrastructure evidence, not field-validation effectiveness evidence.
