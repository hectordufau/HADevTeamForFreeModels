# V3.2 Phase 4 Report — Decision Attribution & Confidence

**Date:** 2026-09-11
**Branch:** `feature/v3.2-learning-integrity`
**Base:** v3.1.0 + V3.2 Phases 1–3

## Summary

Implemented **Decision Attribution and Confidence** for V3.2: a deterministic,
evidence-based attribution engine that classifies each learning-influenced
decision as **CONFIRMED / PROBABLE / POSSIBLE / NONE**, produces an explainable
`attribution_confidence`, preserves explicit Phase 3 outcome semantics
(IMPROVED / UNCHANGED / WORSENED / UNKNOWN), exposes documented metrics with
explicit denominator semantics, and — critically — **protects the 28 restored
V3.0/V3.1 historical artifacts** from a test-cleanup defect that was silently
deleting them from the working tree.

Full suite: **595 passed** (550 baseline + 45 new Phase 4 tests). Zero
regressions. All 29 git-tracked historical artifacts verified intact on disk
after the entire suite.

## 1. Attribution Record

The `DecisionImpact` dataclass (extended in `harness/planner/v3_integration.py`)
now carries the complete attribution record, preserving the Phase 3 provenance
(`validation_run_id`, `benchmark_id`, `mode`, `execution_id`, `decision_id`,
`evidence` chain) and adding Phase 4 fields:

- `learning_influenced` (existing), `experience_ids`, `strategy_ids`
- `retrieval_confidence`, `strategy_confidence` (0..1 or None)
- `baseline_decision`, `selected_decision` (kept separate from
  baseline/actual choice, no conflation)
- `outcome` (IMPROVED/UNCHANGED/WORSENED/UNKNOWN), `outcome_improved` (legacy)
- `attribution_level` (CONFIRMED/PROBABLE/POSSIBLE/NONE)
- `attribution_confidence` (deterministic 0..1)
- `attribution_rationale` (list of human-readable reasons)
- `comparative_used`, `causal_evidence_insufficient` (flags)
- `evidence` (execution/verification/evaluation references)

`from_dict`/`to_dict` are backward compatible: legacy V3.1 files lacking the
new fields reconstruct losslessly (None fields default safely). No synthetic
evidence is ever created; the engine classifies only actual persisted inputs.

## 2. Attribution Levels (Deterministic)

`harness/learning/attribution.py` implements the engine. All thresholds are
documented constants (see `document_thresholds()`); there are NO opaque
numbers. Deterministic rules, evaluated in order (first match wins):

- **R0** — `learning_influenced` is false → **NONE**.
- **R1** — influenced but selected decision == baseline decision → **NONE**
  (learning produced no observable change in the choice, so its effect on the
  outcome cannot be attributed).
- **R2** (causation gate) — if outcome is **UNKNOWN**, any causal level above
  POSSIBLE is refused regardless of confidence → **POSSIBLE** (correlation
  only; UNKNOWN is not harm and not silent-improvement).
- **R3 CONFIRMED** — influenced + decision changed + **complete** evidence
  chain (execution+verification+evaluation) + measured outcome
  (!= UNKNOWN) + internal confidence ≥ 0.70.
- **R4 PROBABLE** — influenced + decision changed + partial evidence chain +
  measured outcome + internal confidence ≥ 0.40.
- **R5 POSSIBLE** — everything else that is influenced + changed but fails a
  higher gate (incomplete chain, weak confidence, or unsupported influence).
- Decisions with **no evidence at all**, or with an **unsupported influence
  claim** (influenced=true but no experience_ids, strategy_ids, or confidence
  signal), are explicitly flagged `causal_evidence_insufficient=True` and
  capped at POSSIBLE.

## 3. Outcome Semantics (Phase 3 preserved)

Outcome remains **IMPROVED / UNCHANGED / WORSENED / UNKNOWN** (canonical in
`OUTCOMES`). **UNKNOWN is never coerced to False, never counted as harm, and
never silently treated as improvement.** UNKNOWN contributes only to the
explicit `unknown_decisions` counter; it is not placed in the improvement or
harm numerator/denominator unless explicitly counted by the documented
metrics above.

## 4. Attribution Inputs

Only actual persisted evidence is consumed: the fields listed in §1 plus the
Phase 3 `evidence` chain (execution/verification/evaluation) and
`comparative_outcome`. `AttributionInputError` rejects malformed inputs
(non-boolean `learning_influenced`, invalid outcome, confidence outside
[0,1]). Nothing is synthesized.

## 5. Attribution Confidence (Explainable)

`compute_attribution_confidence()` is a documented, deterministic, monotonic
function:

```
internal = max(retrieval_confidence, strategy_confidence present) ; 0 if none
confidence = internal * 0.70 + (1 if decision_changed else 0) * 0.30
```

Every result carries an `attribution_rationale` explaining WHY it was
classified as it was (e.g. *"Decision changed vs baseline with a complete
evidence chain … internal confidence 0.80 ≥ 0.70 …"*). The input digest
(`input_digest`) persists the exact evidence used for auditability.

## 6. Counterfactual Distinction

- Comparative outcome (`comparative_outcome`, e.g. "LEARNED>COLD") is a
  **supporting signal only**; it is recorded via `comparative_used` and never
  by itself promotes a decision above the level its evidence chain supports.
- **LEARNED score > COLD score does NOT automatically become CONFIRMED.** A
  decision with a strong comparative signal but an empty evidence chain is
  POSSIBLE with `causal_evidence_insufficient=True` (verified by
  `test_learned_beats_cold_alone_is_possible_not_confirmed`).
- Full counterfactual runs are driven by the Phase 3 COLD baseline recording
  (`influenced_by_learning=False` impacts persist as counterfactuals). Phase 4
  does NOT fabricate counterfactual outcomes; when evidence is insufficient it
  records `causal_evidence_insufficient=True` rather than invent a result.

## 7. Metrics

`AttributionMetrics` exposes (documented in `AttributionMetrics.to_dict()`):

- `learning_influenced_decisions`
- `improved_decisions`, `unchanged_decisions`, `worsened_decisions`,
  `unknown_decisions`
- `decision_improvement_rate` = improved / learning_influenced
- `learning_harm_rate` = worsened / learning_influenced
- `attribution_confirmed/probable/possible/none`

**Denominator semantics (documented):** improvement_rate and harm_rate use the
learning-influenced decision count as denominator. UNKNOWN outcomes are
**excluded from the numerator** (not improvement, not harm) but remain in the
denominator without being assumed to be failures. This is explicitly stated in
the emitted `denominator_semantics` field of the summary.

## 8. Attribution Provenance

Every result is traceable to `validation_run_id`, `benchmark_id`, `mode`,
`task_id` (via context), `execution_id`, and `decision_id`. The evidence chain
is: Decision → Learning influence (experience_ids/strategy_ids) →
Experience/Strategy → Selected decision → Execution → Verification →
Evaluation → Outcome → Attribution.

## 9. TEST Protection

`DecisionImpactTracker.attribution_summary()` **excludes TEST-mode impacts**
from `learning_influenced_decisions` and the metrics. TEST attribution may be
computed for evaluation but never becomes training knowledge (preserving
Phase 2/3 protections). Verified by `test_test_never_becomes_training`.

## 10. Cross-Run Isolation

Attribution is scoped per `ExperimentContext`; each tracker resolves to its
own namespaced store (`artifacts/v3.2/<run>/<mode>/decisions/`). Run A's
impacts, modes, and attribution never leak into Run B (Phase 3 fail-closed
guarding preserved). Verified by `test_cross_run_isolation` and
`test_cold_vs_learned_isolated`.

## 11. Historical Artifact Protection (CRITICAL — DEFECT FIXED)

**Defect found:** `tests/unit/test_v32_storage_isolation.py` defined
`_clean_all_artifacts()`, called once at module import, which removed
**ALL** directories under `artifacts/` — including the 28 git-tracked
restored V3.0/V3.1 historical benchmark artifacts
(`artifacts/experiences_v3/`, `artifacts/gen_experiences/`,
`artifacts/exploration_results/`, `artifacts/experiences/`) and
`artifacts/performance_v3/registry.json`. Running the suite silently deleted
these protected files from the working tree (recoverable via git, but a
violation of the protection requirement).

**Fix:** `_clean_all_artifacts()` now derives the set of git-tracked paths
(from `git ls-files artifacts/`, run at the repo root) and **skips any
directory that contains git-tracked files**. If git status is unknowable it
refuses to delete anything (conservative). The conftest cleanup
(`tests/conftest.py`) already only targeted `artifacts/v3.2/` and needed no
change.

**Regression tests added:**
- `test_cleanup_never_removes_git_tracked_artifacts` — runs the guarded
  cleaner and asserts every tracked artifact still exists on disk.
- `test_all_tracked_historical_artifacts_intact` — direct invariant that no
  git-tracked artifact is missing from disk.

The 28 artifacts + `registry.json` were **restored** from git (they had been
deleted by the prior defect) and verified intact after the full suite.

## 12. Tests

`tests/unit/test_v32_attribution.py` (45 tests) covers:
- Attribution levels CONFIRMED/PROBABLE/POSSIBLE/NONE
- Outcome combos IMPROVED/UNCHANGED/WORSENED/UNKNOWN + UNKNOWN≠harm
- Learning influence (influenced, not influenced, missing/unsupported evidence)
- Evidence quality (complete chain → CONFIRMED, partial → PROBABLE,
  insufficient → POSSIBLE)
- Confidence deterministic + rationale present + no synthetic evidence +
  documented thresholds + invalid-input rejection
- Comparative vs causal: LEARNED>COLD alone does NOT auto-Confirm
- Metrics: improvement/harm rate denominators, unknown count, attribution counts,
  zero-denominator safety, explicit denominator semantics
- Isolation: run A≠run B, COLD≠LEARNED, TEST≠training
- Persistence: attribution survives tracker reload + disk round-trip
- Tracker integration: `attribution_summary`, `run_attributions`
- Historical artifact protection regression
