## 2. Implementation

### 2.1 KnowledgePolicyEngine (`harness/policy/knowledge_policy.py`)

Subordinate domain policy component for Engineering Knowledge governance.

**Architecture:**
- Operates as a domain-specific policy component within the canonical PolicyEngine hierarchy
- Does NOT create a competing authority structure
- Single canonical precedence source: `get_canonical_precedence()`

**Canonical hierarchy:**
```
PolicyEngine (canonical)
├── Execution Policy
├── Tool Policy
├── Autonomy Policy
└── Knowledge Policy (subordinate/domain component)
     └── KnowledgePolicyEngine
          ├── Authority Transition Policy
          ├── Protected Operation Policy
          ├── Security Authority Policy
          ├── Strategy Admissibility Policy
          └── Agent-Generated Knowledge Policy
```

**Key types:**
- `PolicyDecision` — structured policy decision (no bare booleans)
- `Authorization` — explicit authorization provenance for protected operations
- `KnowledgePolicyMetrics` — deterministic descriptive metrics

**Protected operations:**
- `PROPOSED_TO_ACCEPTED` — authority escalation
- `SEC_TO_AUTHORITY` — security authority grant
- `SEC_EXCEPTION_APPROVAL` — security exception
- `WAIVE_SEC` — SEC waiver
- `DEPRECATE_PROTECTED` — protected deprecation
- `CHANGE_AUTHORITY` — authority change
- `CHANGE_STATUS_PROTECTED` — protected status change

**Fail-closed semantics:**
- Missing authorization → DENY
- Unknown authority → DENY
- Unknown transition → DENY
- Terminal state transition → DENY

### 2.2 KnowledgePolicyBridge (`harness/policy/knowledge_bridge.py`)

Bridge between canonical PolicyEngine and KnowledgePolicyEngine.

**Responsibilities:**
- Integrates KnowledgePolicyEngine as a subordinate component
- Provides convenience functions for common knowledge policy operations
- Ensures unified audit trail

**Convenience functions:**
- `evaluate_adr_acceptance()` — ADR acceptance governance
- `evaluate_sec_authority_grant()` — SEC authority governance
- `evaluate_tdr_resolution()` — TDR resolution governance
- `check_self_approval()` — self-approval detection

### 2.3 PolicyEngine Integration (`harness/policy/__init__.py`)

Extended PolicyEngine to include KnowledgePolicyEngine as a subordinate domain component.

**Changes:**
- `PolicyEngine.__init__()` now creates `knowledge_policy` and `knowledge_bridge` attributes
- `PolicyEngine.evaluate_knowledge_operation()` convenience method added
- Existing functionality fully preserved (backward compatible)

### 2.4 Single Canonical Precedence Definition

```python
PRECEDENCE_GOVERNANCE = 7
PRECEDENCE_SECURITY_AUTHORITY = 6
PRECEDENCE_AUTHORITATIVE_ENG_KNOWLEDGE = 5
PRECEDENCE_ACCEPTED_ENG_KNOWLEDGE = 4
PRECEDENCE_TASK_REQUIREMENTS = 3
PRECEDENCE_VERIFIED_EVIDENCE = 2
PRECEDENCE_LEARNED_KNOWLEDGE = 1
PRECEDENCE_EXPLORATION = 0
```

All consumers use `get_canonical_precedence()` — no copy-pasted precedence arrays.
