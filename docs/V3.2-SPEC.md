# V3.2 Master Implementation Plan

## Learning Integrity, Causal Attribution & Experimental Reproducibility

**Base version:** `v3.1.0`
**Target branch:** `feature/v3.2-learning-integrity`
**Target tag:** `v3.2.0` (conditional on all gates passing)

---

## 1. Mission

Implement V3.2 as a **hardening and measurement-integrity** release for the V3.1 learning system.

The primary objective is **not** to add new agent roles, new model families, or substantially expand functionality.

The primary objectives are:

1. **Guarantee strict COLD/LEARNED isolation** across all storage paths and artifact types.
2. **Persist all learning-related decision impacts** and wire real execution outcomes into `outcome_improved`.
3. **Make experiments reproducible and attributable** (validation_run_id, seed-controlled exploration).
4. **Replace artificial baselines** (hard-coded `0.5`) with empirical COLD baselines.
5. **Integrate failure-derived learning** into the V3.1 StructuredExperience pipeline.
6. **Make significance thresholds configurable**, not hard-coded.
7. **Preserve all V3.1 behavior and governance guarantees.**
8. **Preserve all 423 existing tests** — zero regressions.

---

## 2. Motivation

The V3.1 field validation produced strong results:

| Metric | COLD | LEARNED | Delta |
|---|---|---|---|
| Success Rate | 48.5% | 81.5% | +33.1pp |
| Avg Score | 0.4933 | 0.6553 | +0.1620 |
| Decision Improvement Rate | — | 100% | PASS |
| Learning Harm Rate | — | 0% | PASS |

However, the V3.2 Evidence Backlog (`docs/V3.2-EVIDENCE-BACKLOG.md`) identified structural weaknesses in the measurement infrastructure:

- **Mode discrimination is incomplete** — COLD/LEARNED separation exists at the validation runner level but is not enforced across all 6+ storage pathways
- **DecisionImpactTracker is in-memory-only** — `_impacts` is lost on re-instantiation; persisted files exist but are not reloaded
- **`outcome_improved` is mostly `None`** — `record_outcomes()` was never wired into the execution→evaluation lifecycle
- **Generalization baseline is hard-coded to `0.5`** — masks real COLD vs LEARNED generalization comparison
- **Exploration is non-deterministic** — `random.random()` with no seed control
- **Failure lessons skip the V3.1 pipeline** — are stored in V3 ExperienceStore only
- **Significance threshold hard-coded at 5pp** — not configurable per deployment

These are **integrity and validity issues**, not feature gaps. V3.2 closes them.

## 5. PHASE 1 — Unified Experiment Context

### 5.1 Create `ExperimentContext` dataclass

In `harness/learning/context.py`:

```python
@dataclass
class ExperimentContext:
    validation_run_id: str
    benchmark_id: str
    task_id: str
    execution_id: str
    mode: str  # "COLD" | "LEARNED" | "TEST"
    reproducibility_seed: int = 0
    timestamp: str = field(default_factory=lambda: datetime.utcnow().isoformat())
```

### 5.2 Context propagation

Every module in the learning pipeline that persists or retrieves artifacts must accept an `ExperimentContext` parameter.

### 5.3 Context serialization

`ExperimentContext` must be serializable to dict/JSON and storable alongside every artifact.

### 5.4 Tests

- Context persistence and deserialization
- Context propagation through pipeline
- COLD/LEARNED context isolation
- TEST context isolation
- Cross-run context isolation

## 7. PHASE 3 — Decision Impact Integrity

### 7.1 Fix `DecisionImpactTracker`

**Problem:** `_impacts` is in-memory only; file store exists but is not reloaded on `__init__`.

**Fix:**

```python
class DecisionImpactTracker:
    def __init__(self, storage_dir: str, context: ExperimentContext = None):
        self.storage_dir = storage_dir
        self.context = context
        os.makedirs(self.storage_dir, exist_ok=True)
        self._impacts = self._load_persisted_impacts()  # NEW
```

Add `mode` and `validation_run_id` fields to `DecisionImpact`.

### 7.2 Wire `record_outcomes()` into execution lifecycle

The benchmark execution loop must call:

```python
tracker.record_outcome(
    decision_id=decision.decision_id,
    outcome="PASSED" | "FAILED",
    score=result.score,
    improved=decision_outcome_improved
)
```

`outcome_improved` must be set based on an explicit comparison:

- `True` if the learning-influenced decision outperformed the empirical COLD baseline
- `False` if it underperformed
- `None` if no baseline exists for comparison
- `UNKNOWN` explicitly (not missing)

### 7.3 Always record COLD baseline decisions

In COLD mode, always store a `DecisionImpact` even when `influenced_by_learning=False`. This provides the counterfactual for LEARNED mode comparison.

### 7.4 Tests

- Impact persistence and reload across process restarts
- `record_outcomes()` correctly sets `outcome_improved`
- COLD mode records baseline decisions
- LEARNED mode records influenced decisions with outcomes
- `get_summary()` correctly aggregates IMPROVED/UNCHANGED/WORSENED/UNKNOWN

## 8. PHASE 4 — Learning Attribution

### 8.1 Attribution record

For every learning-influenced decision, record:

```yaml
learning_influenced: true|false
experience_ids: [...]
strategy_ids: [...]
retrieval_confidence: float
strategy_confidence: float
baseline_decision: str
selected_decision: str
outcome: PASSED|FAILED
outcome_improved: IMPROVED|UNCHANGED|WORSENED|UNKNOWN
attribution_confidence: float  # how certain we are of the attribution
```

### 8.2 Confidence tiers

The system must distinguish:

- **CONFIRMED** — learning clearly caused the decision change AND the outcome is measurable
- **PROBABLE** — learning influenced the decision but other factors may have contributed
- **POSSIBLE** — learning and decision correlate but causation is not established
- **NONE** — no learning influence detected

### 8.3 Metrics

```text
Learning Influenced Decisions
Decision Improvement Rate
Decision Harm Rate
Unknown Outcome Rate
Attribution Confidence Distribution
```

### 8.4 Tests

- Attribution recorded for every LEARNED-mode decision
- Attribution levels correctly assigned
- Missing attribution data does not default to IMPROVED
- Attribution survivability across process restarts

## 9. PHASE 5 — Empirical Evaluation

### 9.1 Remove hard-coded generalization baseline

**Current (evaluation.py:145):**

```python
baseline_gen = 0.5  # random baseline
generalization_gain = gen_gain - baseline_gen
```

**Required:**

```python
# Use empirical COLD baseline
cold_test_avg = ...  # from COLD test split
generalization_gain = learned_test_avg - cold_test_avg
```

### 9.2 Preserve the distinction

Report separately:

```text
training_improvement:       LEARNED_TRAIN - COLD_TRAIN
validation_improvement:     LEARNED_VALIDATION - COLD_VALIDATION
test_generalization:        LEARNED_TEST - COLD_TEST
generalization_gap:         LEARNED_TRAIN - LEARNED_TEST
```

### 9.3 Configurable significance threshold

Replace hard-coded `success_improvement >= 0.05`:

```yaml
evaluation:
  significance:
    success_rate_pp: 0.05   # configurable percentage points
    score_delta: 0.01       # configurable score delta
    min_samples: 10         # minimum executions for statistical claim
```

### 9.4 Bootstrap confidence intervals

Where sample size permits, calculate 95% bootstrap confidence intervals for success rate and score deltas.

### 9.5 Tests

- Empirical baseline correctly computed
- Configurable thresholds affect significance output
- Bootstrap CI calculation (where implemented)
- All prior evaluation tests remain green

## 10. PHASE 6 — Reproducible Exploration

### 10.1 Seed-controlled exploration

Replace `random.random()` with a seeded PRNG:

```python
class AdaptiveExplorationPolicy:
    def __init__(self, config: dict, seed: int = 0):
        self._rng = random.Random(seed)
        self.exploration_rate = config.get("rate", 0.10)
```

### 10.2 Determinism guarantee

The same (`task`, `learning_state`, `seed`, `config`) must produce the same exploration decision.

### 10.3 Exploration ablation

Add a `LEARNED_NO_EXPLORATION` mode for controlled experiments:

```yaml
exploration:
  enabled: true
  rate: 0.10
  seed: 42
```

When `enabled: false`, the system uses the greedy best-known choice.

### 10.4 Tests

- Same seed → same exploration decision
- Different seed → different exploration decision
- `enabled: false` → zero exploration
- Exploration state is reproducible across process restarts

## 19. Final Note

The purpose of V3.2 is to make the evidence produced by the learning system **more trustworthy, reproducible, and causally attributable** — not merely to make benchmark numbers larger.

The strong V3.1 results (+33.1pp success rate, +0.1620 score) are evidence that learning works. V3.2 must prove that we can measure it correctly.
