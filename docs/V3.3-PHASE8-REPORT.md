## 5. KnowledgeRetriever Architecture

### Selection Mechanism (Not Canonical Store)
- KnowledgeRetriever is a selection mechanism, NOT a canonical store
- KnowledgeStore remains canonical for Engineering Knowledge
- EngineeringKnowledgeGraph remains derived structural relationships
- Retrieval is read-only: no status updates, no authority changes, no mutations

### Retrieval Flow
```
Task/Query Context
    ↓
KnowledgeRetriever.retrieve(query)
    ↓
KnowledgeStore + EngineeringKnowledgeGraph
    ↓
Candidate records
    ↓
scope/authority/status filtering
relationship expansion
deterministic ranking
budget enforcement
    ↓
RetrievalResult
    ↓
KnowledgeContextManager
    ↓
EngineeringKnowledgeContext
```

### Deterministic Ranking Signals (in priority order)
1. Explicit reference (seed record_ids)
2. Graph distance (0=seed, 1=direct, 2=indirect)
3. Record type relevance (task-driven, NOT role-driven)
4. Scope match (project, component, capability)
5. Authority (accepted > proposed; SEC authority separate)
6. Status (current > historical)
7. Structured tag/component match

No Python hash. No set order. No SQLite row order. No filesystem order. No global RNG. No LLM preference.

## 6. Mandatory vs Optional Context

### Mandatory (Protected Knowledge)
- SEC records with ACCEPTED or AUTHORITATIVE authority
- Accepted ADR/DR (authoritative engineering knowledge)
- Accepted requirements that constrain the task

### Optional (Supporting Context)
- Historical RCA, related TDR, learned supporting context
- Proposed records
- Lower-relevance records

### Budget Invariant
- selected optional context <= available optional budget
- Mandatory protected knowledge follows explicit policy
- If mandatory knowledge alone exceeds hard context limit: CONTEXT_OVERFLOW / NEEDS_HUMAN

## 7. Security/Protected Knowledge

### SEC Authority
- SEC records with ACCEPTED or AUTHORITATIVE authority are mandatory
- SEC protected knowledge cannot be dropped by ordinary ranking/budget competition
- Security precedence: Governance > Security Authority > Authoritative Eng > Accepted Eng > Task Requirements > Learned > Exploration

### Security Fail-Closed
- When conflict cannot be safely resolved: FAIL CLOSED
- Never choose newest, agent confidence, learned strategy, or faster plan
- Unresolved conflicts raise KnowledgeConflictError

## 8. Budget Model

### Context Budget
- `budget`: Maximum records to return (default 20, always bounded)
- `estimated_cost`: Deterministic cost per record (record_size + summary_size + relationship_metadata)
- Budget calculation is reproducible

### Budget Enforcement
1. Mandatory items always included
2. Optional items fill remaining budget
3. If mandatory alone exceeds budget: ContextOverflowError
4. Never returns complete knowledge base by default

## 9. Projection

### Bounded Projections
- ADR with id, title, decision, rationale summary, authority, relationships
- Canonical full record remains in KnowledgeStore
- Content is bounded projection, not full record

## 10. Graph Expansion

### Bounded Structural Expansion
- `max_graph_depth`: Maximum traversal depth (default 2)
- `max_graph_nodes`: Maximum nodes to traverse (default 50)
- `allowed_relationships`: Optional filter on relationship types
- Graph distance influences relevance: explicit seed (0), direct relation (1), indirect relation (2)

## 11. Supersession

### Supersession-Aware Retrieval
- Normal current-context retrieval prefers effective record
- Historical query may return both
- Superseded records labeled historical, not silently injected as current
- Uses existing effective-record semantics for ADR, RCA, other superseding families

## 12. Contradictions

### Contradiction Awareness
- Retriever does not silently return contradictory records as coherent truth
- Uses existing ContradictionDetector
- CONTRADICTS edges detected and surfaced
- Unresolved conflicts raise KnowledgeConflictError

### Conflict Resolution
- Where authority hierarchy resolves conflict: preserve result (Learned vs SEC → SEC wins)
- Where authority does NOT resolve: return KNOWLEDGE_CONFLICT
- Do not arbitrarily select

## 13. Authority

### Authority ≠ Relevance
- A highly authoritative record may be unrelated
- A highly relevant record may have low authority
- Authority and relevance are separate signals in ranking

### Authority Hierarchy
- Governance (6) > Security Authority (5) > Authoritative Eng (4) > Accepted Eng (3) > Task Requirements (2) > Learned (1) > Exploration (0)
- No timestamp precedence. No role precedence. No model precedence.

## 14. ContextManager Integration

### Distinct Context Layers
```
KnowledgeContextManager
 ├── Task Context
 ├── Engineering Knowledge Context (EngineeringKnowledgeContext)
 ├── Learning Context (LearningContext)
 └── Evidence Context (EvidenceContext, by reference)
```

### Engineering/Learning/Evidence Separation
- EngineeringKnowledgeContext: PRD, NFR, ADR, TDR, RSK, SEC, RCA
- LearningContext: StructuredExperience, FailureLesson, Strategy, DecisionImpact
- EvidenceContext: EvidencePackage references (by ID only)
- Three-domain separation maintained

### Provenance
- Every context item retains: source domain, record ID, record type, authority, status, retrieval reason
- Evidence references preserved as IDs, never copied

### Context Ordering
- Deterministic: Governance → Security Authority → Authoritative Eng → Accepted Eng → Task Requirements → Other Eng → Learning → Exploration

## 15. Digests

### Context Digest + Retrieval Digest
- Deterministic SHA-256 digests for reproducibility
- RetrievalResult.digest: SHA-256 of sorted items + metrics
- EngineeringKnowledgeContext.digest: SHA-256 of sorted items
- Overall digest: SHA-256 of all context layer digests

## 16. Metrics

### Retrieval Metrics
- candidate_count: Total candidates considered

- budget_used: Total estimated cost
- budget_remaining: Remaining budget

- conflict_count: Conflicts detected

## 17. Coverage

### Protected Knowledge Coverage
- Required: applicable protected SEC missed by retrieval = FAIL when applicability can be deterministically established
- SEC records with ACCEPTED or AUTHORITATIVE authority are always included when applicable

## 18. E2E Scenarios

### Architecture Task
Seed REQ-001, retrieve REQ/NFR/ADR/SEC/TDR/RSK under bounded budget. SEC protected knowledge survives.

### Budget Pressure
Small optional budget, drop lower-priority optional historical context. SEC mandatory knowledge survives.

### Conflict
ADR-A vs ADR-B CONTRADICTS, both applicable → KNOWLEDGE_CONFLICT. Fail closed.

### Security vs Learning
SEC vs Learning → SEC protected, Learning lower precedence.

### Restart
Persist, retrieve, capture digest, restart, repeat → identical output.
