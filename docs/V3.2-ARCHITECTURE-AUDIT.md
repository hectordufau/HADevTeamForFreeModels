### 3.6 Key Architecture Issues

1. **DecisionImpactTracker._impacts is in-memory only** — File store exists but is never reloaded on `__init__`. Impacts are lost on re-instantiation.
2. **`record_outcomes()` modifies in-memory only** — After updating `outcome_improved` on in-memory impacts, changes are not persisted back to disk.
3. **No COLD baseline recording** — `DecisionImpactTracker` only records learning-influenced decisions; COLD-mode decisions are excluded.
4. **`outcome_improved` is never empirically computed** — Always set from `entry.get("outcome_improved")` with no automatic baseline comparison.
5. **Exploration is non-deterministic** — Uses `random.random()` directly with no seed control (`AdaptiveModelPolicyV3`, line 210).
6. **Failure-to-pipeline bypasses V3.1 pipeline** — Failures go to V3 `ExperienceStore` only, not to the V3.1 `StructuredExperience` pipeline.
7. **Generalization baseline is hard-coded to 0.5** — In evaluation.py (not in scope but flagged by spec).
8. **No mode filtering on retrieval** — All retrievals (ExperienceStore, MultiFactorRetriever, PlanLearningStore, EvidenceStore) return results across all execution modes.
9. **No ArtifactContext or timestamp-to-run mapping** — No mechanism to trace an artifact back to its originating validation run.

## 5. Phase 1 Preparation Notes

- **ExperimentContext** dataclass must be created in `harness/learning/context.py` (as specified)
- Minimum fields: `validation_run_id`, `benchmark_id`, `task_id`, `execution_id`, `mode`, `reproducibility_seed`, `timestamp`
- Every store class listed above must accept an `ExperimentContext` parameter in `__init__` and propagate it through all storage/retrieval operations
- Every object type dataclass must gain `mode` and `validation_run_id` fields (or an `ExperimentContext` reference)
- `PlanOutcome` must be created
- `FailureLesson` (or equivalent) must be created with provenance fields
- Directory structure must change to: `artifacts/v3.2/<validation_run_id>/<mode>/<store_type>/`
