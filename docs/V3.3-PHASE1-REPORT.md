## 5. Architecture Decisions

### 5.1 Base Class Approach

All 8 record types (PRD, NFR, DR, ADR, TDR, RSK, SEC, RCA) inherit from a single `EngineeringRecord` base class. This provides:

- **Shared identity** — record_id, record_type, timestamps
- **Shared provenance** — required Provenance dataclass
- **Shared authority** — explicit authority levels
- **Shared lifecycle** — per-type state machine
- **Shared relationships** — typed RecordRelationship
- **Shared versioning** — version + superseded_by
- **Shared validation** — validate() method
- **Shared serialization** — to_dict/from_dict with deterministic round-trip

### 5.2 Stable Identity

- Record IDs follow pattern `TYPE-NNN` (e.g., `PRD-001`, `ADR-042`)
- ID prefix must match record_type
- No Python hash() dependency — compute_hash() uses SHA-256 of canonical JSON
- Deterministic serialization — sorted keys, no object identity

### 5.3 Provenance

- Required for all records (missing provenance rejects record)
- Fields: author, source, timestamp, experiment_context, evidence_refs, parent_record, validation_run_id, benchmark_id, mode
- Integrates with V3.2 ExperimentContext
- Immutable after creation

### 5.4 Authority

- Explicit levels: proposed, accepted, deprecated, archived
- Never inferred from creator, agent role, record type, or file location
- Hierarchy: proposed < accepted < deprecated < archived
- Valid transitions: proposed→accepted, accepted→deprecated, deprecated→archived
- No skipping, no downgrade, archived is terminal

### 5.5 Lifecycle

- Per-type state definitions in lifecycle.py
- Generic transition() function with fail-closed validation
- Terminal states are immutable
- Self-transitions are not valid
- Invalid transitions raise LifecycleError

### 5.6 Relationships

- 14 relationship types (REQUIRES, SATISFIES, DECIDED_BY, CONSTRAINED_BY, INTRODUCES, MITIGATES, SUPERSEDES, CAUSED_BY, RESOLVED_BY, VERIFIED_BY, SUPPORTED_BY, CONTRADICTS, RELATES_TO, DERIVED_FROM)
- Stable references (record_ids), not embedded records
- Self-references rejected
- Provenance optional per relationship

### 5.7 Versioning

- version field (starts at 1)
- superseded_by field for supersession chain
- create_new_version() method preserves provenance chain
- New versions start as proposed authority
- Protected fields: record_id, created_at, original provenance

## 11. Known Limitations

1. **Typed record subclasses deferred** — PRD, NFR, DR, ADR, TDR, RSK, SEC, RCA typed subclasses with domain-specific fields are deferred to Phases 4-7. Phase 1 provides the base class and factory function only.

2. **Relationship validation deferred** — Dangling reference detection, duplicate detection, and cycle detection are deferred to Phase 3 (KnowledgeGraph).

3. **No persistence** — KnowledgeStore is deferred to Phase 2.

4. **No retrieval** — KnowledgeRetriever is deferred to Phase 8.

5. **No governance integration** — KnowledgeGovernance is deferred to Phase 12.
