## 4. Reviewer Architecture

### Independence
```
Planner (creates plan) → Reviewer (evaluates independently)
                         ↑
                    Evidence Store (canonical)
```

Reviewer does NOT trust Planner claims. Reviewer evaluates:
- Task Contract
- Plan provenance
- Execution results
- Verification results
- Evidence references
- Security constraints
- Knowledge context

### Review Statuses
- **PASS**: All requirements satisfied, no violations, all evidence present
- **FAIL**: Violations detected (SEC, evidence integrity, plan drift, etc.)
- **UNVERIFIED**: Required evidence missing
- **CONFLICT**: Unresolved conflicts block review
- **NEEDS_HUMAN**: Plan drift, knowledge drift, or other intervention needed

### Fail-Closed Principles
- Missing required evidence → UNVERIFIED/FAIL, never PASS
- Corrupt/wrong evidence → cannot PASS
- No evidence by absence of contradiction → never PASS
- SEC violation → FAIL even if all functional tests pass
- Plan drift → NEEDS_HUMAN (cannot PASS)
- Knowledge drift → NEEDS_HUMAN (cannot PASS)

Tampered evidence → integrity failure → cannot PASS.
Wrong task/execution evidence → cannot PASS.

## 6. Traceability Architecture

### Cross-Domain Chain
```
PRD → REQ → NFR → ADR → TASK → PLAN → EXECUTION → VERIFICATION → EVIDENCE → REVIEW
         ↑_________________________|
         TDR/RSK/SEC/RCA side constraints
```

### Three Distinct Concepts
```
RETRIEVED → INFLUENCED → COMPLIED/VIOLATED/UNVERIFIED
```

Never infer one from another.

### Stable Identity
Every traceable object uses stable identity:
- REQ ID (e.g., "REQ-001")
- ADR ID + version (e.g., "ADR-004" + version=2)
- Task ID (e.g., "TASK-001")
- Plan ID/digest
- Execution ID
- Verification ID
- Evidence ID (content hash)
- Review ID

No object pointers, no Python hash(), no temporary array indices.

### Deterministic Digest
```python
# Sorted canonical trace edges + source versions + target IDs + relation/status
# + evidence bindings → SHA-256
digest_input = json.dumps({"edges": edge_dicts}, sort_keys=True)
digest = hashlib.sha256(digest_input.encode()).hexdigest()
```

No dependency on Python hash(), set order, filesystem order, SQLite row order, global RNG, or LLM ordering.

### Rebuild Determinism
Same canonical state → same logical traceability, independent of process restart/order.

## 8. Security Precedence

SEC is release-critical:
- Applicable SEC constraints require appropriate evidence
- Reviewer cannot mark compliant solely because Planner included SEC
- Reviewer cannot mark compliant solely because execution succeeded
- SEC violation → FAIL even if all functional tests pass
- SEC unverified → UNVERIFIED, not PASS

### SEC Coverage Metrics
- `applicable_sec`: Total applicable SEC constraints
- `sec_reviewed`: SEC with verification performed
- `sec_evidenced`: SEC with required evidence
- `sec_violated`: SEC violations detected
- `sec_unverified`: SEC without verification

## 9. Knowledge Influence Outcome Trace

For each material KnowledgeInfluence:
```
EngineeringRecord → KnowledgeInfluence → Plan Decision → Execution → Verification → Evidence → Review Result
```

### Outcome Statuses
- **SATISFIED**: Evidence supports compliance
- **VIOLATED**: Evidence shows violation
- **UNVERIFIED**: No evidence available
- **NOT_MEASURABLE**: Influence exists but cannot be measured by current verification

### Retrieved But Not Influenced
Do NOT create fake outcome traces for merely retrieved records.
RETRIEVED but not INFLUENCED may have context provenance but not a decision influence outcome.

### Influenced But Not Verifiable
Represent as: INFLUENCED, OUTCOME = UNVERIFIED/NOT_MEASURABLE.
Do NOT fabricate evidence.

## 10. Plan/Knowledge Drift Detection

### Plan Drift
If `execution.plan_id != plan.plan_id` or `execution.plan_digest != plan.plan_digest`:
→ PLAN_DRIFT → Review cannot PASS → NEEDS_HUMAN

### Knowledge Drift
If `plan.knowledge_context_digest != current knowledge digest`:
→ KNOWLEDGE_DRIFT → may require revalidation/replanning → NEEDS_HUMAN

## 11. TDR/Risk/RCA Handling

### TDR Resolution Claims
If plan claims TDR resolved but no remediation evidence:
→ TDR_UNSUPPORTED_CLAIM violation
→ TDR remains unresolved

### Risk Status
Risk ACCEPTED remains distinct from mitigated/resolved.
Reviewer does NOT infer Risk accepted = Risk mitigated.

### RCA Influence
If RCA corrective/preventive action influenced planning:
RCA → Influence → Plan → Verification → Evidence → Review

## 14. Traceability Completeness

- **COMPLETE**: All applicable requirements have plan + verification + evidence
- **PARTIAL**: Some requirements traced but not all
- **BROKEN**: Broken traces detected
- **UNVERIFIED**: Traces exist but verification status unknown

Critical: **COMPLETE does NOT mean PASS**. A complete trace can still be FAIL.

Example: REQ → Plan → Execution → Verification FAIL → Evidence → Reviewer FAIL.
Traceability is COMPLETE. Compliance is FAIL.
