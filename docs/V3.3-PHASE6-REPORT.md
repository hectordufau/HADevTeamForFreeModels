## 4. TDR Schema

```yaml
id: TDR-001
title:
description:
debt_type: code | design | architecture | test | documentation | dependency | process | infrastructure
severity: critical | high | medium | low
impact:                    # How the debt affects the system
remediation:               # How to fix it
remediation_estimate:      # Effort estimate
target_condition:          # Condition for resolution
priority: critical | high | medium | low
owner:                     # Optional owner reference
target_milestone:          # Optional milestone reference
resolution_evidence: []    # Evidence record IDs
related_decisions: []      # ADR/DR IDs
status: identified | acknowledged | remediation_planned | in_progress | resolved | closed
authority: proposed | accepted | deprecated | archived
provenance:
relationships:
```

### TDR Lifecycle
```
identified → acknowledged → remediation_planned → in_progress → resolved → closed
```

Invalid transitions FAIL CLOSED. Agent-generated TDR always starts as PROPOSED.

## 5. RSK Schema

```yaml
id: RSK-001
title:
description:
risk_category: technical | schedule | resource | security | compliance
likelihood: high | medium | low          # Qualitative only — no fabricated precision
impact: high | medium | low              # Qualitative only
exposure: critical | high | medium | low  # Derived from likelihood × impact
mitigation:                             # Mitigation strategy
mitigation_owner:                       # Optional owner reference
contingency:                            # Contingency plan
related_decisions: []                   # ADR/DR IDs
related_security: []                    # SEC IDs (mitigation/control)
status: identified | assessed | mitigated | accepted | closed
authority: proposed | accepted | deprecated | archived
provenance:
relationships:
```

### RSK Lifecycle
```
identified → assessed → mitigated → accepted → closed
```

Critical distinction: ACCEPTED means consciously accepted (risk still exists), NOT resolved. MITIGATED means mitigation actions taken. CLOSED means risk no longer relevant.

### Risk Exposure Matrix (Qualitative)

| Likelihood \ Impact | High | Medium | Low |
|---------------------|------|--------|-----|
| High | critical | high | medium |
| Medium | high | medium | low |
| Low | medium | low | low |

## 6. SEC Schema

```yaml
id: SEC-001
title:
description:
category: CONSTRAINT | CONTROL | FINDING | THREAT | REQUIREMENT
enforcement:                       # How the constraint is enforced
related_nfrs: []                   # NFR IDs
related_adrs: []                   # ADR IDs
related_risks: []                  # RSK IDs
related_tdrs: []                   # TDR IDs
waiver:                            # Waiver record_id (if constraint is waived)
exception_approved: false          # Agent cannot self-approve exception
status: active | waived | expired | deprecated
authority: AUTHORITATIVE | ACCEPTED | PROPOSED | INFERRED | HISTORICAL | DEPRECATED
provenance:
relationships:
```

### SEC Lifecycle
```
active → waived → expired → deprecated
```

### SEC Authority Hierarchy
```
AUTHORITATIVE (5) > ACCEPTED (4) > PROPOSED (3) > INFERRED (2) > HISTORICAL (1) > DEPRECATED (0)
```

Agent-generated SEC always starts as PROPOSED. Security authority must NOT be inferred from record_type == SEC.

## 11. Security Conflict Behavior

### Deterministic Conflict Detection

| Conflict Type | Detection | Resolution |
|---------------|-----------|------------|
| ADR_CONTRADICTS_SEC | ADR PROPOSED contradicts authoritative SEC | SEC WINS — ADR cannot be accepted |
| REQ_CONTRADICTS_SEC | REQ contradicts authoritative SEC | SEC WINS — REQ cannot override SEC |
| TDR_RESOLVED_WITHOUT_EVIDENCE | TDR claims resolved but no evidence | FAIL CLOSED — cannot be RESOLVED |
| RISK_STATE_CONFLICT | High-exposure risk ACCEPTED | REVIEW — should not be merely accepted |

### Critical Invariants

1. **Learning cannot override SEC** — SEC authority outranks Learned Knowledge
2. **Task preference cannot override SEC** — SEC authority outranks Task Requirements
3. **ADR cannot silently override SEC** — ADR PROPOSED CONTRADICTS SEC → CONFLICT
4. **Agent cannot self-approve protected security exception** — exception_approved defaults to False
5. **Security authority must NOT be inferred from record_type == SEC** — explicit authority field required
