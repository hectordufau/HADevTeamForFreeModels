# V3.2 Phase 6 Report — Reproducibility & Deterministic Exploration

**Date:** 2026-09-11
**Branch:** `feature/v3.2-learning-integrity`
**Base:** v3.1.0 + V3.2 Phases 1–5
**Scope:** Phase 6 ONLY (spec §10). Phases 7–8 NOT implemented, no release/tag,
no merge to master.

## Summary

Phase 6 makes exploration fully **reproducible and deterministic**, separating
learned execution into `COLD` / `LEARNED_NO_EXPLORATION` (greedy best-known) /
`LEARNED_EXPLORATION` (deterministic seeded) / `TEST`, while preserving backward
compatibility with legacy `LEARNED` artifacts (never reinterpreting historical
data).

The deterministic core lives in a new module **`harness/learning/determinism.py`**
and is wired into the V3.1 exploration paths
(`harness/planner/model_intelligence.py::AdaptiveModelPolicyV3`,
`harness/learning/exploration.py::AdaptiveExplorationPolicy`) so that their
exploration decisions no longer consume the global RNG. The invariant holds:

> same task + same learning state + same seed + same config
>   => same exploration decision => same selected strategy/model/policy
>   => same execution plan.

The full suite is **677 passed** (638 baseline + 39 new Phase 6 tests + 0
regressions). All **29 git-tracked historical artifacts remain intact**. The
Phase 5 statistical pipeline still produces **identical** results
(`scripts/phase5_empirical_evaluation.py --split test`).

> **CRITICAL — this report contains REAL execution evidence, not placeholders.**
> The examples below were produced by actually running
> `scripts/phase6_reproducibility.py` and `scripts/phase5_empirical_evaluation.py
> --split test`. The persisted decision JSONs are on disk under
> `artifacts/v3.2/V3.2-REPRO-20260911/LEARNED_EXPLORATION/exploration/`.

## 1. Deterministic randomness (spec §2)

- **Forbidden global-RNG use removed.** `random.random()` / `random.choices()`
  on the module-global RNG were removed from the learning/exploration paths:
  - `AdaptiveModelPolicyV3.select()` — explore gate now uses a local
    `random.Random(seed)` (was `random.random()`).
  - `AdaptiveModelPolicyV3._explore()` — top-N weighted pick now uses a local
    seeded `random.Random` (was `random.choices(...)`).
  - `AdaptiveExplorationPolicy.should_explore()` — now uses a local seeded
    `random.Random(seed)` (was `random.random()`).
- **Seed derivation** (`derive_exploration_seed`) is **SHA-256** over

  ```
  sha256(f"{reproducibility_seed}::{validation_run_id}::{benchmark_id}::
          {task_id}::{decision_scope}")[:16]  (int)
  ```

  It NEVER uses Python's built-in `hash()` (process-randomized for strings,
  hence non-reproducible across process boundaries). The derived seed is
  persisted with every decision's evidence.
- **Global RNG untouched.** Verified: running 3 deterministic decisions leaves
  `random.getstate()` byte-for-byte unchanged (`GLOBAL RNG UNCHANGED BY
  EXPLORATION: True`).

## 2. Experiment modes (spec §3)

`VALID_MODES` extended to `{COLD, LEARNED, LEARNED_NO_EXPLORATION,
LEARNED_EXPLORATION, TEST}`. Legacy `LEARNED` remains valid and readable.
Semantic groupings are explicit and separate (so legacy data is never silently
reinterpreted):

| Mode | Learning | Exploration | Meaning |
|---|---|---|---|
| `COLD` | no | forbidden (greedy) | baseline |
| `LEARNED` (legacy) | yes | *superset* (historical; not reinterpreted) | legacy |
| `LEARNED_NO_EXPLORATION` | yes | forbidden (greedy) | greedy ablation |
| `LEARNED_EXPLORATION` | yes | enabled (seeded) | seeded exploration |
| `TEST` | never trains | — | held-out |

Helper predicates: `exploration_is_disabled()`, `exploration_is_enabled()`,
`is_learned_mode()`, `effective_exploration_rate()`. `namespace_path` /
`check_test_protection` accept the new modes; `TEST` learn/train protection is
unchanged (TEST can never enter training stores).

## 3. LEARNED_NO_EXPLORATION — greedy (spec §4)

`DeterministicExplorationPolicy.deterministic_decision()` selects the best-known
eligible candidate with a **fully deterministic tie-break**:

```
primary_score DESC, confidence DESC, historical_utility DESC, stable_id ASC
```

implemented as an ascending sort key (`-primary, -confidence, -utility, id`),
so the result depends only on the candidate *set*, never on dict/set insertion
or iteration order (R5/R6). No RNG outcome influences the decision in this mode
(R4).

## 4. LEARNED_EXPLORATION — deterministic seeded (spec §5)

Exploration reuses the **existing V3.1/V3.2 semantics** (draw against the
confidence-adaptive rate; top-3 weighted pick), but the draw and the weighted
pick both use a single experiment-scoped `random.Random(seed)` derived from the
context. **No new optimization algorithm** was introduced — Phase 6 is
reproducibility, not redesign.

## 5. Exploration-disabled config (spec §6)

`learning.exploration.enabled: false` (in `config/harness.yaml`) → the policy
forces `exploration_probability=0`, `exploration_taken=false`, and greedy
best-known selection. Also honored by `LEARNED_NO_EXPLORATION` mode and by an
explicit `ExplorationContext.exploration_enabled=False`. Verified (R4): 30
different seeds all yield the same single decision.

Also exposed programmatically by `load_exploration_config(config)`.

## 6. Exploration evidence (spec §7)

Every learning-influenced decision records (via `ExplorationDecision.to_dict()`):
`mode`, `enabled`, `configured_rate`, `exploration_taken`, `reproducibility_seed`,
`derived_seed`, `decision_scope`, `candidate_ids`, `selected_candidate_id`,
`selection_reason`, and where known `greedy_candidate_id` /
`exploratory_candidate_id`. It is persisted by
`persist_exploration_decision()` into the namespaced v3.2 tree. The
`would_selection_differ()` helper answers **"would Harness have selected
differently if exploration were disabled?"** — always computable here because
the greedy candidate is always available; it never fabricates a counterfactual
when the greedy candidate is not computable (returns `computable: False`,
`would_differ: None`).

## 8. Reproducibility tests R1–R6

`tests/unit/test_v32_determinism.py` (39 tests):

- **R1 same seed** — same seed ⇒ same decision, repeated; full evidence equal.
- **R2 process restart** — derived seed recomputed in a fresh subprocess
  matches; context persisted → re-hydrated via `from_dict` ⇒ same derived seed,
  candidate ordering, decision.
- **R3 different seed** — sweep over seeds yields >1 distinct exploratory path;
  real Example 2 above.
- **R4 exploration disabled** — 30 seeds with `LEARNED_NO_EXPLORATION` (and with
  `exploration_enabled=False`) all yield the same single decision;
  `exploration_taken=False`; equals greedy exactly.
- **R5 greedy determinism** — best-known always selected; tie-break by
  confidence, historical utility, stable id; deterministic across repeats.
- **R6 candidate ordering** — reversed/shuffled input yields identical greedy
  pick and identical seeded decision / candidate ordering.

Plus: seed-derivation SHA-256 correctness, no-Python-hash, no-global-RNG
(Pyright/pytest), evidence persistence + counterfactual, governance/advisory,
Phase 5 compatibility, no eval→learning feedback, and export availability.

## 9. Experiment isolation (spec §9)

`validation_run_id` / `benchmark_id` / `mode` / `task_id` / `execution_id` each
feed the seed derivation, so different runs/benches/tasks/scopes get different
deterministic seeds. The evidence is namespaced under
`artifacts/v3.2/<run_id>/<mode>/exploration/`. `TEST` protection and
COLD/LEARNED/TEST cross-contamination checks are unchanged. New learned modes do
not bypass Phase 2 isolation (`namespace_path` + `check_test_protection`
unchanged in intent; verified by the Phase 2 isolation suite still passing).

## 10. Historical compatibility (spec §10)

- All **29 git-tracked historical artifacts remain intact** (verified: count =
  29, every tracked path present after the full suite and the guarded cleanup
  tests).
- Legacy `mode: LEARNED` artifacts remain **readable** — `LEARNED` stays in
  `VALID_MODES`, so persisted/legacy contexts serialize and deserialize without
  migration. **No historical artifacts were migrated, rewritten, or deleted.**
- **Legacy LEARNED mapping (spec §11):** the Phase 5 statistical pipeline
  (`statistics.py`) keeps `COLD` as the baseline arm and treats `LEARNED` as the
  canonical learned arm. Phase 6's new learned modes
  (`LEARNED_NO_EXPLORATION`, `LEARNED_EXPLORATION`) are **not retroactively
  injected** into historical data; a defensive `_is_learned_mode()` maps them to
  the learned arm *if* ever encountered, leaving COLD/TEST meaning and current
  results identical.

## 12. No eval→learning feedback (spec §12)

`DeterministicExplorationPolicy.deterministic_decision()` is a pure function of
its inputs: it writes no strategies, experiences, model/workflow/agent policy,
or routing. Verified by `test_no_eval_to_learning_feedback` (the artifacts tree
is unchanged after a decision) and by the report generator being read-only.

## 13. Security / governance (spec §13)

Learning + exploration is **advisory only**: `DeterministicExplorationPolicy`
and `AdaptiveModelPolicyV3` only *recommend* a candidate; they never override
PolicyEngine, autonomy limits, security gates, governance, tool perms, or
forbidden-change rules. An exploratory candidate that violates policy is
**REJECTED** by the existing governance gates (e.g. `FreeModelInvariantEnforcer`
and the planner's policy checks) — exploration never justifies weakening
security/governance. Tests assert the advisory module carries no authorization
and never mutates learning state. **Free-model invariant preserved** (all model
selection still gated by `FreeModelInvariantEnforcer`; only free models appear
in the exploration candidate set).
